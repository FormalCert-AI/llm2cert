# Baseline acceptance

Supported sets use the final eligibility manifest. Native successes retain
each method's original certificate semantics. Strict checks preserve the
problem's unrelaxed conditions using the method-specific certification path:

- FOSSIL and analytical-RL require conclusive SMT results.
- SynNLF removes the derivative offset in its SOS check.
- CBF uses its interval-bound certification conditions. Its four successes
  comprise one exported-model replay and three saved native acceptances
  under the same unrelaxed conditions.

The native union contains 19 systems. Eleven native successes remain accepted
under Strict accounting. The Full framework verifies 40 of the 51 supported
systems. The targeted FOSSIL record for DCB-OURS-P4-001 ended in a timeout
under its 2,400-second budget.

Saved acceptances are reused only where the mathematical problem is unchanged.
The release includes acceptance evidence and adapters; fresh baseline runs
also require the upstream implementations, trained candidates, and applicable
licenses.
